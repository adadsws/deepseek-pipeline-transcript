# 修复空白 cue 与坏翻译缓存

## 需求

- 修复仅含 `-` 等无正文 cue 导致整个视频失败的问题。
- 空白或无正文 cue 即使修复后也要计入错误统计。
- DeepSeek 集中重试必须真正重新请求，不得重复使用已知缺译缓存。
- 不清空所有视频的共享缓存，不重复处理已有正确 SRT。
- 用此前失败的三个视频进行真实回归。

## 设计

- 新增源 SRT 清洗：仅删除不含任何 Unicode 字母或数字的正文块，保留时间轴有效且有语言内容的块，并连续重编号。
- 清洗事件记为 `invalid_or_blank_srt`，随后再次严格校验；如果清洗后没有有效 cue，仍作为失败处理。
- 集中重试 DeepSeek 类错误时，为对应视频设置刷新标记；翻译线程临时绕过 LLM 响应缓存，并以真实新响应覆盖分块翻译缓存，运行结束后恢复默认缓存行为。
- 初次处理和非 DeepSeek 重试仍使用现有缓存，以控制时间和费用。
