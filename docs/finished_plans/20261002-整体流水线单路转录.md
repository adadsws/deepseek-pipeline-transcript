# 整体流水线与单路转录实施计划（已完成）

## 已确认需求

- [x] FasterWhisper 正式模型继续固定为 `medium`。
- [x] 整批处理采用一个端到端任务流水线，不把“流水线”仅定义为翻译并发，也不建立彼此割裂的转录、翻译子流程。
- [x] 每个视频依次流过“排队/预检 → GPU 门禁 → 转录 → 源 SRT 校验与清理 → DeepSeek 翻译 → 双语终检 → 原子发布 → 报告”。
- [x] 转录工位固定仅 1 个工作线程、任意时刻只处理 1 个视频。
- [x] 一个视频完成转录后立即流入源字幕后处理及其余下游工位；转录工位随即处理下一个视频。
- [x] 不同视频可同时位于不同工位；单个视频全部阶段成功后才创建最终 SRT。
- [x] 整轮不存在“全部转录完再统一开始下游”或固定四视频组之间的阶段屏障。

## 最小实现

- [x] 复用现有转录、清理、翻译、校验和发布函数，只重构阶段边界与 `process_video_group` 调度。
- [x] 转录执行器固定 `max_workers=1`；ASR 清理移入下游工位，使其可与下一视频转录重叠。
- [x] `videos_per_batch` 保留兼容字段名，语义改为整条流水线的最大同时在途数；默认滑动窗口为 4。
- [x] 下游执行器继续采用配置的最多 4 路并发；完成一个视频后立即向滑动窗口补入下一个。
- [x] 跳过、转录失败、翻译失败、人工重试轮、临时目录清理与按输入顺序汇总语义保持不变。

## 验证与交付

- [x] 调度测试证明转录最大并发数严格为 1、整轮只进入一次流水线且转录可与源字幕清理及后续阶段重叠。
- [x] 运行 89 项全量测试、编译检查、配置检查及固定上游 clean 检查。
- [x] 使用两个 30 秒真实视频片段完成 `medium`/CUDA 冒烟测试；使用本地假翻译，不调用 DeepSeek。
- [x] 更新 README、CHANGELOG 与 AGENT_CONTEXT，统一描述整条流水线。
- [x] 归档计划、编写精简复盘并只提交本任务文件。

真实冒烟结果：两个片段分别生成 4 条和 2 条有效字幕并成功原子发布；第 1 个视频下游运行于 20.817–32.819 秒，第 2 个视频转录运行于 20.893–27.815 秒，实际重叠 6.922 秒；两次转录均由唯一的 `videocaptioner-transcribe_0` 工作线程完成。
