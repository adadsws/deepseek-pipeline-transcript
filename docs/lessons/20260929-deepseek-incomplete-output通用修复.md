# DeepSeek 不完整输出修复复盘

## 项目专项复盘

- `deepseek_incomplete_output` 是最终完整性分类，不等于单一模型错误；必须结合 LLM 请求日志和上游 chunk 失败日志区分纯标点清空、空响应与网络中断。
- 上游翻译缓存以 10 句分块存储，但轮末重试可以在分块内按字幕编号合并，只请求空译文句，兼顾缓存兼容与 Token 节省。
- 本地 HTTP 响应钩子读取失败后不得访问 `response.text`；应先记录原始读取异常，再原样抛出，让 SDK 的重试和诊断看到真正原因。

## 跨项目通用实践

- 后处理应保持“非空不变为空”的不变量；清理标点、标签或格式前后都应验证该性质。
- 面对批量任务的部分失败，优先保存并复用最小成功单元，再只重试失败单元，不应默认重做完整批次。
- 错误分类只能用于汇总；根因判断必须保留最接近故障源的异常类型、响应状态和原始上下文。
