# `config` 目录纯配置化重构复盘

## 项目专项复盘

- 上游路径常量无需修改：把 `AppData/models`、`cache`、`logs` 和 `resource/bin` 改为精确 Junction，既能分流数据，又能保持固定上游 Git clean。
- GUI 配置应以 TOML 为持久来源，QConfig JSON 只作运行时兼容产物；Key 字段必须保持为空，由独立 secret 桥在实际调用边界注入。
- `batch` 与 `gui` 的叶子字段完全成对、`shared` 禁止重复叶子，可用结构测试防止设置归类随维护漂移。
- 大资源迁移前后应至少校验主可执行文件、FFmpeg 和模型主体的 SHA-256；仅比较目录大小不足以证明内容未变。
- 同一缺陷只保留一个权威补丁。空译文校验放在翻译韧性补丁后，批处理不再临时覆盖相同上游方法。

## 跨项目通用实践

- 配置目录只保存声明式文本；固定依赖、可重建缓存、审计日志和历史证据分别进入资源、临时、输出和归档边界。
- 迁移大型目录时先建立并验证新代码路径，再同盘移动数据，最后切换兼容链接，可缩短不可用窗口并降低回滚成本。
- Windows Junction 的删除与重建应拆成显式绝对路径操作；先验证 LinkType 和目标，禁止用递归删除处理链接。
- 运行时生成的兼容配置必须视为临时文件，不能成为第二个持久配置源，也不能复制真实密钥。
