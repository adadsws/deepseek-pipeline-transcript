# 批处理流水线结构简化复盘

## 项目专项复盘

- 转录执行器每次只提交一个任务并立即等待，真正的阶段重叠来自仍在运行的下游执行器；移除该包装不影响流水线吞吐。
- `videos_per_batch` 已不表示固定分组，继续保留会误导配置维护；改为 `max_in_flight` 后与滑动窗口背压语义一致。
- 仅用于描述既有实现、生产代码从不读取的功能开关不应留在运行配置中；安全不变量仍由代码和测试保证。
- 最终控制台汇总改为消费报告共用汇总结构，避免同一批次数据存在两套独立计算。

## 跨项目通用实践

- 判断流水线是否真实，应验证不同任务的不同阶段在时间上重叠，而不是检查是否创建了某个线程池。
- 同步生产者配合异步消费者也能形成真实流水线；没有排队收益的单线程执行器只会增加理解成本。
- 配置名称必须描述当前语义，兼容旧名称不应无限期保留；迁移时应同步代码、校验、示例、测试和用户文档。
- 汇总数据应先形成唯一结构，再由控制台、结构化报告和审计日志分别渲染。
