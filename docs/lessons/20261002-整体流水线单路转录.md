# 整体流水线与单路转录复盘

## 项目专项复盘

- 原实现已经重叠转录和翻译，但主线程同步执行转录、ASR 清理仍占用转录阶段，而且每四个视频存在组间完成屏障；不能只凭“有翻译线程池”称为完整流水线。
- 转录改为独立单工作线程工位，ASR 清理移至下游后，GPU 转录可以更早接收下一视频，同时继续保持全局单路。
- 固定分组改为最大在途数为 4 的滑动窗口后，完成一个视频即可补入下一个；既消除组间空转，也限制临时目录和待处理字幕的资源占用。
- 真实 `medium`/CUDA 双片段测试证明上游 `TranscriptThread` 可在转录工作线程正常运行，并与上一视频下游阶段实际重叠；最终发布仍逐视频严格校验。

## 跨项目通用实践

- 判断是否为端到端流水线，应检查任务是否逐阶段流动、不同任务是否能占据不同工位，以及是否存在隐藏的整批阶段屏障。
- 单工作线程阶段仍然是流水线工位；阶段并发数应按资源特性独立设置，而不是要求所有阶段采用相同并发。
- 用滑动在途窗口替代固定分组，可以兼顾持续供给和资源背压；“每批数量”配置迁移为在途上限时必须同步澄清语义。
- 并发测试应使用事件故意制造阶段交错，并另做真实运行时冒烟验证，避免只验证线程池对象存在。
